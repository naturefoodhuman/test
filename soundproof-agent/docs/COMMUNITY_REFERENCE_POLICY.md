# 社区参考与持续对标策略

> 目的：避免项目进入“自嗨式开发”，确保每一轮工程决策都持续参考最新社区实践、官方文档、以及真实平台链路变化。

## 1. 强制原则

从本文件建立后，后续每一轮开发都应遵守以下规则：

1. **先看官方，再看社区，再做实现**
   - 先确认 Playwright / FastAPI / Ollama 等官方推荐做法
   - 再参考 GitHub 高质量项目的落地模式
   - 最后再决定本项目采用何种实现

2. **购物平台链路优先服从真实页面**
   - 如果真实淘宝页面与当前代码假设不一致，必须以真实页面为准
   - 不允许为了保留既有代码而忽略平台真实链路变化

3. **不以“能跑”替代“能维护”**
   - 任何临时修补都必须配套：artifact、注释、回退策略、文档更新

4. **每次实机联调后都要回写文档**
   - 页面结构变化
   - 新发现的稳定选择器
   - 新发现的风险点
   - 新的失败模式

5. **安全边界优先于抓取欲望**
   - 真实执行必须受 URL 白名单、危险路径拦截、验证码即停、频率限制约束
   - 不允许因为追求抓取成功率而放宽高风险边界

---

## 2. 本项目当前重点对标对象

### A. 官方最佳实践

#### Playwright 官方
重点参考：
- 定位器（locator）选择策略
- 自动等待与重试机制
- 不依赖脆弱 DOM 层级的写法

#### Ollama 官方
重点参考：
- 本地模型接入方式
- Anthropic / OpenAI 兼容层能力边界
- 本地上下文长度建议

### B. 社区工程参考

重点不是照搬，而是吸收这些项目在以下方面的思路：

1. **browser-use**
   - 浏览器自动化产品化方式
   - 任务拆分与工具调用边界

2. **Stagehand**
   - 基于 Playwright 的 AI 辅助浏览模式
   - 页面变化下的适配思路

3. **Crawl4AI**
   - LLM 友好的网页抓取与文本抽取经验
   - 对“先抽内容，再给模型”的分层思路

---

## 3. 对标不代表照搬

本项目仍坚持自己的核心原则：

1. **真实淘宝链路优先**
2. **本地模型优先**
3. **确定性浏览器执行优先，LLM 负责理解与归纳**
4. **评论只做第二阶段增强，不一开始全量抓**
5. **反爬策略以保守、低频、可中断、可人工接管为主**

如果社区项目与这些原则冲突，应优先保留本项目的产品目标与安全边界。

---

## 4. 每轮开发前自检问题

后续每一轮开发前，Agent 至少要自问：

1. 这次改动是否已经看过相关官方文档？
2. 这次改动是否有社区成熟实现可参考？
3. 这次实现是否和真实淘宝当前链路一致？
4. 如果页面结构变化，当前实现是否有 artifact 和回退策略？
5. 这次改动是否需要更新 handoff / current_state / backlog 文档？
6. 这次改动是否碰到了安全边界？若碰到，是否优先收敛而不是放宽？
