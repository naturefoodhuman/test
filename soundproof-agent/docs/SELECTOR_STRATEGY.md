# 选择器策略

## 1. 总体原则

本项目参考 Playwright 官方最佳实践：

- 优先使用更稳的定位方式
- 尽量避免深层 DOM 路径依赖
- 允许多级 fallback
- 联调时保留 artifact 以便修复

## 2. 当前实现方式

淘宝相关选择器集中在：

- `src/shopping/selector_profiles.py`

这样做的原因：

1. 页面改版时不必满项目搜字符串
2. 便于下一位 Agent 集中调整
3. 能明确区分：
   - 列表页候选选择器
   - 详情页标题/店铺/价格选择器
   - 评论标签页选择器

## 3. 当前策略不是最终稳定版

因为还没做真实淘宝联调，所以当前选择器属于：

> **基于经验和通用结构的可维护初版**

必须在真实联调后继续更新。

## 4. 联调时应优先记录什么

1. 哪个选择器命中稳定
2. 哪个选择器经常失效
3. 是否需要从 locator 改为页面脚本提取
4. 哪个 artifact 最能帮助修复
