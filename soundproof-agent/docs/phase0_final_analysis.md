# Phase 0 最终分析（Round 1 + Round 2）

## 1. 最终结论

Phase 0 已完成两轮模型评测：

- **Round 1**：`qwen3.6:35b-a3b-q8_0` vs `qwen3:14b`
- **Round 2**：`qwen3-coder-next:q4_K_M`

### 最终路由结论

#### 运行时主模型
- **协调员（F）**：`qwen3.6:35b-a3b-q8_0`
- **噪音分析（A）**：`qwen3.6:35b-a3b-q8_0`
- **方案顾问（B）**：`qwen3.6:35b-a3b-q8_0`

#### 购物模块模型分工
- **购物推理 / 购物总结（D）主模型**：`qwen3-coder-next:q4_K_M`
- **购物字段补归纳 / 轻量备用**：`qwen3:14b`
- **购物总结 fallback**：`qwen3.6:35b-a3b-q8_0`

---

## 2. 为什么这样定

## 2.1 qwen3.6 仍然是全局主模型

原因：

1. 协调员场景下最稳
2. 噪音分析更贴近产品语境
3. 不容易出现领域跑偏
4. 对低频交通噪声的降噪量估计明显优于 qwen3:14b

### 关键证据

- `qwen3:14b` 在 `coordinator_002` 中把预算 3000 误解到了租房/购房语境，属于真实产品中的严重跑偏
- `qwen3.6` 在协调与噪音分析任务中更贴近“隔音窗决策”本身

---

## 2.2 为什么购物主模型切到 qwen3-coder-next:q4_K_M

虽然 `qwen3-coder-next:q4_K_M` 在通用任务上的总分不是最高，但在**你最关心的购物任务**里表现更强：

### Shopping Summary 表现

- `shopping_summary_001`：1.0000
- `shopping_summary_002`：0.9250

相比之下，`qwen3.6` 在购物总结任务上的均值略低一些，且 `qwen3-coder-next` 的输出更像“可执行采购建议”，包括：

- 明确提到 PVB/SGP、低频专项检测、Rw 指标等
- 风险点更偏工程采购视角
- refinement 更接近真实搜索与验收动作

### 局限

- `qwen3-coder-next` 在噪音分析里有明显“英文标签化”倾向
- 不适合作为全局协调模型

### 所以最终定位是

> **只让它负责购物侧的“复杂归纳与决策总结”，不让它接管全局。**

---

## 2.3 为什么 `qwen3:14b` 还保留

因为 Round 1 中：

- 它在短商品文本里提取出了 `hardware_keyword: HOPO执手`
- 说明它做轻量字段补全时较积极

所以它适合当：

- `shopping_field_normalizer`
- fallback
- 低成本归纳模型
