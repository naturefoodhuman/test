# Phase 0 Round 1 结果分析

## 1. 结论先行

Round 1 的自动评分结果显示：

- `qwen3.6:35b-a3b-q8_0` 平均分：**0.8781**
- `qwen3:14b` 平均分：**0.8781**
- 两者 JSON 解析成功率均为：**100%**

但从**逐条语义质量**来看，二者并不是真的“完全打平”。

### 我的人工判定

#### 更适合做 F 协调员 / A 噪音分析 / 购物总结主模型：
- **qwen3.6:35b-a3b-q8_0**

#### 更适合做轻量字段归纳 / 低成本补位模型：
- **qwen3:14b**

#### 结论性质：
- 这是 **Round 1 暂定结论**
- 在进入 Phase 1 前，仍建议做 **Round 2（补测 Qwen3-Coder）**

---

## 2. 为什么自动评分打平，但人工判断不打平

当前 Phase 0 的自动评分主要看：

1. JSON 能否解析
2. 必填字段是否齐全
3. 关键词覆盖率

这套方法适合筛掉“格式不稳”的模型，但还不够区分：

- 追问是否真的问到点子上
- 降噪建议是否合理
- 商品推荐是否真的贴合场景

所以本轮结果说明：

> **两者格式稳定性都很好，但 qwen3.6 的场景理解和决策质量更稳。**

---

## 3. 分角色分析

## 3.1 F 协调员

### qwen3.6 的表现

优点：
- `coordinator_001` 能抓到预算、改造方式、尺寸三个关键槽位
- 追问内容明显更贴近隔音窗咨询实际流程
- 不会把预算 3000 误解到房租/购房场景

问题：
- `coordinator_002` 里仍然漏掉了“是否接受加内窗”这种关键购物导向问题
- 把“隔音窗帘/白噪音设备”并列放进问题，略有偏离本产品主线

### qwen3:14b 的表现

优点：
- 输出结构稳定
- `coordinator_001` 也能问到预算

明显问题：
- `coordinator_002` 出现严重跑偏：把“预算 3000”理解成房租/购房总价
- 这类错误在真实产品里会直接破坏用户信任

### 协调员结论

> **F 协调员主模型应定为 `qwen3.6:35b-a3b-q8_0`。**

---

## 3.2 A 噪音分析

### qwen3.6 的表现

优点：
- 对高架 + 搅拌车低频场景识别准确
- 推荐降噪量 25–35 dB，明显更贴近睡眠场景需求
- 对空调外机低频嗡鸣也给出较合理的局部处理导向

### qwen3:14b 的表现

优点：
- 能识别“交通噪声 + 低频”
- 结构化输出同样稳定

明显问题：
- 对 `noise_001` 的建议隔声量只有 15–20 dB，偏保守
- 对 `noise_002` 给出 5–10 dB，也偏低
- 这意味着它在“要做多强的隔音”这件事上可能偏弱

### 噪音分析结论

> **A 噪音分析主模型也应优先 `qwen3.6:35b-a3b-q8_0`。**

---

## 3.3 购物抽取 / 字段归纳

### qwen3.6 的表现

优点：
- 抽取稳定
- 商品标题、价格、玻璃规格、服务项都能提取出来

问题：
- `shopping_extract_001` 里漏掉了 `hardware_keyword`

### qwen3:14b 的表现

优点：
- 在同一条样例中多提取了 `hardware_keyword: HOPO执手`
- 说明它对短商品文本里的细节字段归纳略积极一些

### 抽取结论

> 当前 Round 1 下，**轻量字段归纳可让 `qwen3:14b` 先承担 fallback 或辅助角色**。

但要注意：

- 真正的列表页 / 详情页抓取，V1 主链还是应该以**确定性解析**为主
- LLM 更适合做“字段标准化”和“缺失字段补归纳”，而不是当唯一抽取器

---

## 3.4 购物总结 / 购物决策

### qwen3.6 的表现

优点：
- `shopping_summary_001` 明确选择 B 店（夹胶中空 + 三道密封）
- 理由更贴近“高架低频 + 睡眠 + 一站式方案”
- 风险提示和后续搜索 refinement 更完整

问题：
- `shopping_summary_002` 中写了“中空层需充氩气等惰性气体才能发挥最佳隔音效果”，这个表述不宜直接进入生产规则，需要后续用知识库约束

### qwen3:14b 的表现

优点：
- `shopping_summary_002` 选择 B 店是合理的
- 结果结构完整，内容也可用

明显问题：
- `shopping_summary_001` 选择了 C 店（单层夹胶，靠后续加内窗）
- 这不是绝对错误，但对“当前用户要性价比高、尽量直接落地”的语境来说，不如 qwen3.6 稳

### 购物总结结论

> **D 的“购物决策总结”主模型也暂定 `qwen3.6:35b-a3b-q8_0`。**

## 5. Round 2 是否还有必要

### 结论：**有必要**

原因不是 Round 1 失败，而是：

1. **你的 V1 价值核心是购物模块**
2. 购物模块最吃“工具调用 / 复杂字段整理 / 商品归一化”能力
3. 当前 Round 1 只证明：现有模型可用，但还没证明“有没有更适合购物链路的模型”

所以我建议继续测：

- `qwen3-coder:30b-a3b`

Round 2 要重点比较：

1. 商品字段补全能力
2. 复杂报价表解析能力
3. 结构化输出稳定性
4. 对详情页噪声文本的规格归纳能力
