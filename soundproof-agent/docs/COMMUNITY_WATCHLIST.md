# 社区对标观察清单

> 本文档不追求“收集越多越好”，而是只保留对当前阶段真正有参考价值的项目与观察点。

## 1. 浏览器与网页抓取类

### browser-use
当前主要观察点：
- 任务级浏览器自动化产品化方式
- 如何组织页面操作与模型推理边界
- 浏览器执行器与高层 agent 的分层

当前项目已吸收的做法：
- 不把全部逻辑直接交给浏览器 agent
- 保持“确定性执行主链 + 模型做理解和归纳”
- 用 artifact、历史、报告、事件统计做可追溯性

### Stagehand
当前主要观察点：
- Playwright 之上的 AI 辅助浏览思路
- 页面结构变化时的适配策略
- 缓存与回放能力思路

当前项目已吸收的做法：
- 先抽象执行器接口，再逐步补真实实现
- 先保留 artifact，再修选择器
- 先做 replay，再做 live

### Crawl4AI
当前主要观察点：
- 抓取文本清洗
- 面向 LLM 的网页内容抽取结构
- 先提纯文本、再交给模型的工作方式

当前项目已吸收的做法：
- 列表与详情页先抽文本和结构
- 再进行 LLM 字段补归纳与总结
- 让 Markdown 报告、历史快照与 artifact 共存，方便追溯

## 2. 官方文档类

### Playwright 官方文档
当前重点跟踪：
- locator 策略
- auto-wait / retry 能力
- 更稳的选择器写法

当前项目已吸收的做法：
- 尽量避免脆弱 CSS 层级依赖
- 优先考虑可回退的提取策略
- 保留 HTML / JSON / 截图 artifact 用于回溯
- 真实链路前增加 risk probe / diagnostics / login check

### Ollama 官方文档
当前重点跟踪：
- 本地模型兼容能力
- Anthropic 兼容层
- 本地上下文长度建议

当前项目已吸收的做法：
- 模型路由独立化
- 购物总结与字段补归纳分开建服务层
- CLI / API / service 层共享同一模型路由，不在业务代码写死

## 3. 当前对本项目最有价值的社区经验

### 已吸收的经验

1. **不要把全部逻辑交给 AI 浏览器代理**
   - 先做确定性浏览器执行主链
   - LLM 做理解、补归纳、总结

2. **先规则后模型**
   - 列表过滤、字段抽取、排序优先规则化
   - LLM 在规则之上补全与判断

3. **要保留 artifact 便于修复**
   - HTML
   - JSON
   - 文本
   - 截图

4. **评论要做有效性识别，而不是只做情绪统计**

5. **反爬策略要内建到执行链，而不是后补**
   - 搜索频率
   - 详情页批量抓取上限
   - 验证码即停
   - 人工接管

6. **诊断能力要和主链一起演进**
   - preflight
   - diagnostics
   - event stats
   - artifact inspection
   - latest report / latest run
