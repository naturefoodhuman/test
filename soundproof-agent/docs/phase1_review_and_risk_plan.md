# 商品评论与反爬风险策略计划

本文件回应两个关键产品问题：

1. 商品参数满足需求后，是否抓评论作为选购参考？
2. 如何应对购物平台的反爬虫策略及封号风险？

## 1. 商品评论策略

### 结论

**要抓，但不应一开始就对所有候选商品抓评论。**

推荐采用两阶段策略：

### 阶段 A：结构先行
先基于下面信息筛出前 3~5 个候选：

- 玻璃结构
- 密封结构
- 型材/窗型
- 价格与预算匹配
- 安装服务

### 阶段 B：评论审查
只对前 3~5 个候选补抓评论，做“评论审查”而不是简单情绪统计。

## 2. 有效评论识别原则

### 更可能是有效评论的特征

- 提到具体规格：如夹胶、中空、三道密封、断桥铝
- 提到具体场景：如临街、地铁、低频、大车、漏风
- 提到真实使用后变化：如“安装后噪音小了”“仍有漏风”
- 文本较长，带有细节和因果
- 带图或提到安装过程

### 更可能是刷评/模板化评论的特征

- 极短高分评论，如“很好”“满意”“不错”
- 没有任何产品细节或场景信息
- 评价语高度模板化
- 只表达购买态度，不表达使用体验

## 4. 反爬虫与封号风险策略

### 总原则

不是“想办法绕过平台”，而是把行为控制在：

- 慢
- 少
- 可解释
- 可停止
- 可人工接管

### 具体策略

1. **真实浏览器 + 本地持久化 profile**
   - 不使用高频 API 爬取
   - 不使用大规模并发

2. **单次抓取数量受限**
   - 搜索次数限流
   - 单次详情页数量受限
   - 评论抓取只针对少量候选

3. **遇到验证码立即停止自动执行**
   - 不自动撞验证码
   - 切人工接管

4. **优先使用缓存**
   - 已抓过的商品优先读 SQLite / artifacts
   - 减少重复访问

5. **测试账号与个人主账号分离**
   - 项目仅使用专用测试账号
   - 降低对日常账号的影响
